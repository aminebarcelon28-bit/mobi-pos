## Method

- **Clustering rule: root cause, not feature area.** A case sits in the one cluster whose fix would make its assertion pass. Verified mechanically: every FAIL id appears in exactly one cluster (251/251, 0 missing, 0 duplicated, 0 phantom).
- **Class**: `app` | `test` | `harness` | `environment` | `bad data`.
- **Evidence class**: `bytes` | `SQLite` | `IPC` | `DOM` | `text` | `none`.
- **Money impact**: `money movement` (cash/value leaves or enters) | `stored value` (a stored balance or total is wrong) | `display only` (a printed/shown number is wrong) | `none`.
- **WEAK** = a FAIL whose only evidence is "nothing threw" or a visible string. The evidence table already records **0 UI-text-only FAILs**; the scan over all 251 reason strings found **0 WEAK** matches.
- **Ranking**: money movement first, then stored value, then confirmed-still-FAIL, then P0 before P1.
- **Catalog**: `.opencode/skills/e2e-testing/references/bug-catalog.md` is lettered A–H; a cluster maps to a letter or is `NEW`.
